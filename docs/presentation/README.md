# Демонстрация для А101 — структура презентации

Материалы к демо-показу движка оптимальной раскладки армирования плит.

| Файл | Что это |
|---|---|
| `deck.html` | Колода на 18 листов. Открывается в браузере, печатается в PDF (Ctrl+P → «Сохранить как PDF», ландшафт, поля «нет»). Стрелки ←/→ листают. |
| `README.md` | Этот файл: структура, доклад по листам, куда подставлять реальные данные. |

Колода описывает конвейер из `run2.py`. Это актуальная точка входа: `run.py` остался
от первой итерации и импортирует `A101.work_cooperative`, которого в репозитории нет.

## Драматургия

Показ построен по схеме **проблема → метод → доказательство → результат → деньги →
границы поставки**. Ключевая мысль, которую нужно донести: *раскладка перестаёт быть
предметом мнения и становится предметом расчёта — вплоть до килограммов в спецификации*.

Четыре опоры, на которые опирается разговор:

1. **Числовое поле вместо картинки.** Пока вход — цвет на экране, спорить можно о чём
   угодно. Как только вход — площадь сечения в см²/м, начинается инженерия.
2. **Номенклатура заказчика внутри задачи.** Классы не выдуманы: они собираются
   из вашего сортамента и фоновой сетки перебором комбинаций слоёв.
3. **Доказанный оптимум, а не «хорошее решение».** Система обязана доказать
   оптимальность. Это проверяемое свойство, а не маркетинговое утверждение.
4. **Результат доведён до стержней.** Не абстрактные зоны, а раскладка на единой сетке
   и спецификация с массой в килограммах, включая анкеровку.

## Доклад по листам

**02. Проблема.** Не критиковать инженеров. Проблема не в квалификации, а в том, что
ручной процесс физически не позволяет перебрать пространство вариантов — значит,
неопределённость закрывается запасом, и величина этого запаса никем не измеряется.

**04. Архитектура.** Главное на листе — пунктирная панель снизу. Все параметры инженера
живут в одном экране настроек в начале расчёта и входят в блоки 02–04, не касаясь
метода решения. Это ответ на вопрос «а если у нас другие требования» до того, как его
зададут.

**06. Квантование.** Здесь ждут подвоха: «вы огрубляете сетку — значит, теряете
точность». Ответ: штраф за сжатие зоны в 30 раз выше штрафа за расширение, поэтому
ошибка огрубления идёт только в запас. Расширить зону — это добавить арматуру,
а не убрать.

**07. Сортамент.** Самый сильный коммерческий лист технической части. Раньше расход
по классам вбивался руками; теперь классы выводятся из каталога заказчика. Стоит
произнести: *«номенклатура перестаёт быть следствием привычки конкретного инженера»*.
Числа на листе можно пересчитать при заказчике (см. ниже).

**09. Модель.** Отличие от простого покрытия: ячейке, которой нужно два слоя, должны
соответствовать две реально уложенные сетки, и это проверяется для каждого порога
отдельно. Занизить армирование модель не может по построению.

**10. Гарантия.** Формулировка, которую стоит произнести дословно: *«оптимальность
здесь — не оценка, а результат, который система обязана доказать; если доказать
не удалось, она не выдаёт это за оптимум»*.

**11. Единая сетка.** Второй сильный лист. Показать схему стыка: до привязки просвет
между крайними стержнями соседних зон меньше допустимого, после — равен шагу. Это
и есть трудоёмкость монтажа в явном виде: на объекте получается одна разметка,
а не пять несогласованных.

**12. Спецификация.** Закрывает вопрос «а что мы получим на руки». Отдельно отметить,
что анкеровка подрезается по фактическому контуру плиты, поэтому масса анкеровки —
посчитанная величина, а не оценка сверху.

**15. Метрики.** Лист интерактивный: поля пересчитываются на лету. Сценарий — спросить
у заказчика его числа и ввести их прямо во время показа. Обязательно проговорить, что
значения в полях сейчас заглушки.

**17. Стандарт и опции.** Принцип разделения: в стандарт входит всё, что нужно, чтобы
получить оптимальную раскладку, довести её до стержней и посчитать массу. В опции
вынесено то, что зависит от контура заказчика.

## Что подставить перед показом

В `deck.html` три места помечены как демонстрационные. Их нужно заменить реальными
данными прогона, иначе на показе придётся оговариваться.

**1. Кривая компромисса (лист 14).** В скрипте:

```js
var PARETO = [[1,.98],[11,.62], ...];   // [N, масса] — нормировано в 0..1
```

Подставить точки реального прогона: число зон и массу из результатов `solve_rectangle_job`
для разных `N`; масса нормируется на максимум. Подпись «Схема формы кривой»
в `figcaption` после этого надо заменить на название плиты и проекта.

**2. Поле требований (листы 01 и 05).** Вызовы `buildField(cols, rows, zones)` рисуют
демонстрационную карту. Можно заменить на реальную матрицу `int_matrix` (после
`loads_to_classes`), выгруженную в виде массива целых.

**3. Входные значения метрик (лист 15).** Атрибуты `value` у полей `#i-*`:

| Поле | Значение | Откуда брать реальное |
|---|---|---|
| `i-slabs` | 240 | данные А101 — плит перекрытий в год |
| `i-runs` | 4 | направления × слои (верх/низ × X/Y) |
| `i-hm` | 3 | хронометраж ручной раскладки, данные А101 |
| `i-ha` | 0.4 | **измеряется на пилоте** |
| `i-hy` | 1700 | полезный фонд времени инженера |
| `i-ce` | 2 800 000 | ФОТ с налогами, данные А101 |
| `i-ms` | 12 | текущая масса арматуры на плиту, данные А101 |
| `i-d` | 6 | **измеряется на пилоте** — перерасход против оптимума |
| `i-ps` | 78 000 | цена арматуры с монтажом, данные А101 |

Две величины помечены как измеряемые на пилоте — их нельзя взять из головы.
Остальные подтверждает заказчик.

## Числа на листе 07 — как пересчитать под другой сортамент

Лист 07 показывает конкретные значения для конфигурации из `run2.py`. Если у заказчика
другой каталог, числа считаются так:

```python
from math import pi
from itertools import combinations_with_replacement

def ds_arm(d, s):                 # площадь сечения на погонный метр, см²/м
    return round(10 * (d / 2) ** 2 * pi / s, 1)

back_grid = (18, 300)
stock = [(18, 300), (20, 150), (20, 100), (25, 150), (25, 100)]
max_lay, anchor_k = 2, 32

back = ds_arm(*back_grid)
arm = [ds_arm(*x) for x in stock]
combs = [()] + [c for n in range(1, max_lay + 1)
                for c in combinations_with_replacement(range(len(stock)), n)]
variants = sorted(back + sum(arm[i] for i in c) for c in combs)
print(len(variants), variants[0], variants[-1])
print({d: anchor_k * d for d, _ in stock})
```

Для текущей конфигурации получается: фон 8,5 см²/м; **21 вариант** полного армирования
в диапазоне **8,5 … 106,7 см²/м**; анкеровка 576 / 640 / 800 мм для Ø18 / Ø20 / Ø25.

## Формулы метрик

```
задач        = плит × (направления × слои)

штат_до      = задач × ч_ручной   / ч_год
штат_после   = задач × ч_проверки / ч_год
эффект_ФОТ   = (штат_до − штат_после) × стоимость_инженера

часы         = задач × (ч_ручной − ч_проверки)

тонны        = плит × масса_плиты × перерасход
эффект_мат   = тонны × цена_с_монтажом

совокупно    = эффект_ФОТ + эффект_мат
```

Экономия на материале — **нижняя оценка**: раскладки лучше доказанного оптимума
не существует, поэтому перерасход измеряется точно — сравнением спецификаций
в килограммах, а не процентами «на глаз».

Время расчёта движка в формулы не входит и в экономию не засчитывается: часть задачи,
не зависящая от числа зон, готовится один раз, точки кривой считаются параллельно
и с тёплым стартом — это минуты, и на фоне ручной раскладки величина пренебрежимая.

## Состав поставки

### Стандарт

- Приём DXF из LIRA-CAD, автоматическое чтение цветовой шкалы и легенды,
  реконструкция поля требуемой площади сечения
- Разделение уровней, сохранение отверстий, точное квантование сетки
  с асимметричным штрафом «сжать / расширить»
- Сборка классов армирования из каталога заказчика и фоновой сетки, перебор
  комбинаций слоёв, подбор класса на каждое требование, анкеровка из диаметра
- Генерация кандидатов с технологическими ограничениями: минимальная ширина зоны,
  сшивка разрывов короче анкеровки
- Точное решение с доказательством оптимальности, два решателя на выбор,
  оба направления и оба слоя, полная кривая компромисса «масса ↔ число зон»
- Постобработка раскладки: единая сетка стержней на всю плиту, минимальный зазор,
  нормированные контакты зон, перепроверка покрытия после сдвигов
- Спецификация: масса в кг с анкеровкой и без, диаметр, шаг, число и координаты
  стержней по каждой зоне, отдельная строка массы анкеровки
- Чертёж зон поверх поля требований, явный отчёт о послаблениях и предупреждениях
- Пакетный расчёт, параллельное исполнение, жёсткие лимиты времени, промежуточные
  решения в реальном времени, диагностика невыполнимых требований
- Передача исходного кода и документации, обучение группы инженеров

### Опции

- Другие расчётные комплексы, прямой обмен с Revit / IFC, нестандартные подложки
- Непрямоугольные зоны — Г-образные и полигональные карты
- Разные сортаменты по секциям и этажам, ограничения поставщика и складских остатков
- Коммерческий решатель для тяжёлых плит; унификация раскладки между этажами и секциями
- Явная стоимостная модель трудоёмкости — нахлёсты, стыки, крановые операции —
  слагаемым целевой функции
- Выгрузка спецификации в Excel / 1С, привязка к сметным расценкам, ведомость
  расхода по этажам
- Обратная запись в DXF, оформление листов КЖ, размерные цепочки
- Веб-интерфейс, плагин к рабочему месту, расчёт всего дома одной постановкой
- Развёртывание в контуре заказчика, SLA, калибровка модели под практику,
  отчёт-обоснование для экспертизы
